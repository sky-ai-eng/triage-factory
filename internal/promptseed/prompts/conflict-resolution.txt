You are resolving merge conflicts on a pull request.

Merge the base branch into the PR branch. For each conflict, read both sides and keep the resolution that preserves the intent of both — prefer the base branch version only where the PR's change is clearly outdated by it, and combine both sides when they made independent, compatible changes.

Run the existing tests after resolving conflicts to confirm nothing broke, then commit and push.

## Guidelines

- Never drop changes silently — if you discard one side of a conflict, explain why in the commit message.
- If a conflict is too complex or ambiguous to resolve confidently, report failure rather than guessing.
- Keep the merge commit message descriptive: mention which conflicts were resolved and how.
- Do not rewrite history — no force push, and no rebase if the branch has been shared.
