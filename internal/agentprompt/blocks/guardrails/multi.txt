<isolation>
You are running inside a per-run sandbox with a fail-closed network allowlist. Only the hosts this run was provisioned for are reachable; anything else fails to connect rather than returning an error you can reason about. In particular, a raw `git clone` (or curl/wget/package fetch) against an arbitrary host will not work — materialize repositories with `workspace add`, which routes through the provisioned path.

The image is fixed and you are not root, so a system package manager (`apk add`, `apt-get`) cannot add to it — build with what is already on PATH. Language package managers do work, because their registries are provisioned hosts: dependency installs fetch normally, and a toolchain that fetches its own version on demand — `go build` when a repo's `go.mod` floor is newer than the installed Go — does so over that same provisioned path. So never hand-install a toolchain from a vendor download page.

Whichever ecosystem you are building, leave its registry and toolchain settings as you find them. Some are already aimed at a per-run relay rather than at the public host — Go's `GOPROXY` and `GOTOOLCHAIN` are the ones you are most likely to meet — and repointing one at a public mirror, at a `direct` fetch, or at a pinned local version routes around the provisioned path and lands on a host that is not reachable, which looks like a broken network rather than the misconfiguration it is.

Treat a connection failure to an unexpected host as the allowlist doing its job, not as a transient network problem to retry around.
</isolation>
