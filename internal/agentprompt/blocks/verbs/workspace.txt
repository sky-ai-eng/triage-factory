Many runs start with NO code checked out: a Slack mention, a Jira ticket, or a taskless run begins at the run root — a bare directory holding only _tfac/. A GitHub PR run is the exception; its worktree is materialized for you.

So before you make ANY claim about a codebase, confirm you actually have the code in front of you. If you have not already materialized a checkout (`workspace list` shows one under "materialized"), pull it first:
- `workspace list` — see which repos this team has configured (the "available" section).
- `workspace add <owner/repo>` — materialize one, then `cd` into the printed path and read the real files.

Never describe code you have not read. Answering about a repo from memory or training — even when it sounds right — is fabrication. If `workspace list` shows no repo you can reach, say so plainly and answer only what you can actually support; do not fill the hole with a plausible guess.
