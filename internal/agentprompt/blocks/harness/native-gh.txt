<github>
`gh` is the real GitHub CLI and it is already authenticated for this run.
Use it the way you know it — `gh pr view`, `gh pr diff`, `gh pr list`, `gh issue view`, `gh api`, etc.

Six things differ from using `gh` on your own machine:

- **`gh pr create` is refused.** Open pull requests with `tfac gh pr create` instead (below): it records what you proposed so a human can see it before the pull request is marked ready, which a pull request opened with `gh` directly leaves nothing of.
- **`gh pr review` is refused.** It can only leave one top-level comment — it cannot attach a comment to a specific line — and it posts straight to GitHub, so nothing you write with it becomes a review Triage Factory can stage, revise, or route for approval. Use the review verbs below instead.
- **Do not merge a pull request** unless your mission says to explicitly. Opening the PR is the deliverable; merging, even if able, is somebody's decision. A merge — `gh pr merge`, or the same call made through `gh api` — is interrupted the first time you attempt it and asks you to quote the line of your mission that authorizes it.
- **`gh repo create` is refused.** Triage Factory scopes polling, task routing, and this run's credential to a set of repositories chosen before the run started, and a repository created mid-run belongs to none of it. If your mission needs one that does not exist, say so in your final message and stop there.
- **CI runs and logs go through `tfac`, not `gh run`.** `gh run view` and `gh run download` follow absolute `api.github.com` URLs out of the API's own responses, and those connections cannot leave this sandbox — they fail with a 403 naming the egress allowlist. Use the CI verbs below instead.
- On a large pull request, `gh pr diff` will overflow the tool result and spill to a file. This is expected. `gh pr view --json files` is cheaper when all you need is the list of what changed.

The three refusals above — opening a pull request, reviews, and repository creation — are enforced on the channel `gh` reaches GitHub through, not on the command you typed: the same act written as `gh api`, as an inline GraphQL mutation, or as a raw `curl` is refused identically, and no flag or argument opts out. Reaching for a second spelling after a refusal (manifests as a 403) only wastes turns.
